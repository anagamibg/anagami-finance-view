# P5 — SSRF и външни URL

Сесия S6 (преглед на сигурността), пакет P5. Дата: 2026-10-28. Покритие: всички изходящи HTTP заявки и обработка на външни URL в `app/**/Databackd/**` (Google Sheets / `csv_url` източници, ECB курсове, dompdf remote, редиректи, URL полета в моделите).

Накратко: преди поправката SSRF защитата на `csv_url` изобщо не важеше при `app.debug=true` (AFV го презаписва от настройка в базата) или при заявка с `Host: localhost`; редиректите не се проверяваха; DNS се резолвираше два пъти; нямаше лимит на размера. Сега: схема САМО `https`, хост САМО `docs.google.com` (при пренасочване и `*.googleusercontent.com`), порт 443, всички A/AAAA адреси публични, връзката е „закована“ към проверените IP-та, редиректите се следват ръчно (макс. 3) с повторна проверка на всеки хоп, лимит 10 MB / 100 000 реда / 5 s connect / 20 s общо, проверка на Content-Type, лимит на честотата. „Локален режим“ вече НЕ разхлабва нищо в URL правилата (само разрешава четене на `public/databackd/templates/*.csv` от диска) и се определя от `APP_URL`, не от `app.debug`/Host/`APP_ENV`.

Промяна в поведението (решение, поискано в задачата): `csv_url` в production вече приема само `https://docs.google.com/...` (напр. таблица „публикувана в мрежата“ като CSV). Произволен `https://моя-сайт.bg/data.csv` вече е отказан. За разширяване — един ред в `GoogleSheetsReader::ALLOWED_HOSTS` (всички IP/redirect/размер проверки продължават да важат).

## Проверено без находки

Проверено с: четене на кода, `grep` по `app/**/Databackd/**`, tinker/PHP скриптове (188 проверки без мрежа + реален тест към Google), HTTP kernel тест на `POST /account/databackd/data/sources/fetch` (админ и служител).

- **Инвентар на изходящите заявки в `app/**/Databackd/**`:** `Http::`/`curl_*`/`file_get_contents('http`/`fopen('http`/`get_headers`/`SimpleXML`/`DOMDocument::load*`/`SoapClient`/PhpSpreadsheet от URL → единствените мрежови места са `GoogleSheetsReader::requestOnce()` (потребителски URL, сега защитен) и `FxRateService::fetchEcb()` (константен ECB URL). `FinSyncController`/`InvoiceExpenseSync` (фактури → `fin_entries`), `ImportFinEntriesJob`, командите в `app/Console/Commands/Databackd/**` (`SendSavedReports`, `RecurringAnalysis`, `Check*`) — без изходящи HTTP заявки; няма автоматично „sync“ по разписание на `fin_data_sources`.
- **Real-world поток:** публична примерна Google таблица се сваля през `docs.google.com → 307 → doc-08-4o-sheets.googleusercontent.com` (200 `text/csv`): и двата хопа валидирани, A+AAAA проверени, връзката заковава IP-тата. Несъществуващо ID → „Таблицата или листът не са намерени“ (HTTP 400/404 → съобщение). Сайтът за вход (private sheet) → „не е публична“ без заявка към `accounts.google.com`.
- **Хостилни входове** (`assertSafeUrl($u, false)`) — всички отказани: `http://docs.google.com/…`, `https://docs.google.com.evil.com/…`, `https://evil.com/?docs.google.com`, `https://evil.com#@docs.google.com/`, `https://docs.google.com@127.0.0.1/`, `https://user:pass@docs.google.com/…`, `https://docs.google.com%2f@evil.com/`, `https://127.0.0.1/`, `https://127.1/`, `https://localhost/`, `https://[::1]/`, `https://[::ffff:127.0.0.1]/`, `https://0x7f000001/`, `https://0x7f.0x0.0x0.0x1/`, `https://0177.0.0.1/`, `https://017700000001/`, `https://2130706433/`, `https://169.254.169.254/latest/meta-data/`, `https://100.64.0.1/`, `https://docs.google.com\.evil.com/`, `file:///etc/passwd`, `gopher://`, `ftp://`, `dict://`, `http://127.0.0.1:8123/login`, `https://docs.google.com:8443/`, `https://docs.google.com:80/`, кирилица/IDN (`https://докс.google.com/`, `xn--…`), CR/LF/NUL/интервал в URL, `https://docs.google.com../`, URL с 2100 знака. Приети: `https://docs.google.com/spreadsheets/d/…/export?format=csv`, `…/d/e/…/pub?output=csv`, главни букви в хоста, завършваща точка и `:443` (нормализирани).
- **DNS (подменен резолвер):** публичен A + `AAAA ::1`, `AAAA fd00::5`, `AAAA ::ffff:127.0.0.1`, A `127.0.0.1`, A `169.254.169.254`, A `10.0.0.5`, A `100.64.0.9`, без записи → всички отказани; публичен A(+AAAA) → приет. Реален DNS на `docs.google.com` → само публични адреси.
- **Редиректи (подменен транспорт):** към `169.254.169.254`, `http://…`, `evil.com`, `127.0.0.1`, `*.googleusercontent.com` със записан частен IP (DNS проверка на хопа), >3 пъти, `Location` с CRLF, без `Location` → отказани и не се правят заявки към опасната цел; относителен и `//host` `Location` → разрешени и следвани.
- **Съдържание/лимити:** HTML → „не е публична“; `application/json` → отказан; ZIP/xlsx байтове → отказани; 100 001 реда → отказани, 100 000 → ок; реален cURL с `MAX_BYTES=2048` към страница от 8 KB → прекъсване с „файлът е твърде голям“.
- **Локален режим:** с `APP_URL=https://databackd.com` и едновременно `app.debug=true`, `app.url=http://127.0.0.1:8123`, `env=local`, заявка с `Host: localhost` → `isLocalDevelopment()=false`, шаблоните НЕ се четат от диска, `http://127.0.0.1:8123/databackd/templates/…` е отказан; с локален `APP_URL` (`localhost`, `127.0.0.1`, `[::1]`, `*.test`, `*.localhost`) → `true`, шаблонът се чете от диска (без HTTP); `../`, `%2F`, `.xlsx`, `.php`, `%00` → отказани. Lookalike `APP_URL` (`evil.com/localhost`, `localhost.evil.com`, `notlocalhost`, `test.com`, празен) → `false`.
- **Контролер (реално през HTTP kernel, CSRF заместен):** `POST …/sources/fetch` с опасни URL → flash грешка, без stash файл; с шаблона в локален режим → редирект към `mapping/<uuid>`; 13-ата заявка за 5 минути → „Твърде много опити…“ (за админ и за служител). Смоук `databackd.data.sources` → 200 (остава само чуждо „untranslated keys: databackd-gaps-alerts.menu“ от Gaps меню, не е свързано).
- **XXE/XML (ECB):** `FxRateService::parseEcb()` отказва `<!DOCTYPE`/`<!ENTITY`, ползва `LIBXML_NONET` без `LIBXML_NOENT`, лимит 2 MB, извлича само атрибути → няма XXE/billion laughs.
- **dompdf `isRemoteEnabled`:** във всички четири PDF класа е `false` (P4), логото е локален файл/`file://`; `config/dompdf.php` `enable_remote => true` е глобален default за upstream PDF-и (фактури) — извън обхват.
- **Показване на URL:** `source_url`/`fin_data_sources.url` се извеждат само през `{{ }}`/`e()` (`sources/index.blade.php:141`, `mapping.blade.php:38`, `result.blade.php:32`, `batches/show.blade.php:107`, `FinImportBatchesDataTable.php:42`) и никъде като `href`.
- **Open redirect:** `redirect(` в AFV контролерите използва само `route()`/`editUrl()`; няма редирект по входен параметър.
- **Други URL полета:** `analysis_requests.deliverable_link` (Teams) — валидира се като `https?://` (`FILTER_VALIDATE_URL`) или път `/…` (`DeliverableAnalysisRequest.php:22-36`), `javascript:` е отказан, само за персонал, показва се през `{{ }}`. Бележка: път от вида `/\evil.com` минава валидацията (браузърите го третират като `//evil.com`); без допълнителен риск, защото персоналът и без това може да въведе `https://evil.com`. Не са намерени webhook/callback полета в моделите на AFV.
- **Stash на свалените файлове:** `storage/app/databackd-imports/<company_id>/<uuid>.csv|json` — токенът се валидира с `Str::isUuid`, директорията е по `company()->id` (няма път от потребителя).

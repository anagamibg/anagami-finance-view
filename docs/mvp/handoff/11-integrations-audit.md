# S11 — одит на страница „Интеграции“

Страница: `/account/databackd/data/integrations`. Одит на всяка интеграция спрямо публичната документация на външния формат/програма, проверка на кода (контролери, услуги, изгледи, преводи) и поправки. След това три независими код ревюта; всички потвърдени забележки са поправени.

## Какво е проверено и поправено

| Интеграция | Основни поправки |
|---|---|
| Excel / CSV | Многолистова книга внасяше **последния** лист и формулите като текст → само първият лист, изчислени стойности, дати от клетки (вкл. 1904); UTF-16 („Unicode Text“), ред `sep=`, разделител с отчитане на кавички; десетичен знак по колона (`detectDecimalSeparators()`), без да се чупят обикновените стойности („12.50“, „0.125“, „1 234,567“); валута в сумата („99,5 лв.“ → BGN); защита от двойно пускане; неуспешен dispatch маркира партидата като неуспешна. `FinEntriesSheetImport` е премахнат (не се ползва). |
| Google Sheets | Линкове `/spreadsheets/u/N/d/…`; име на лист в полето gid → ясна грешка; публикуван линк без gid; точни съобщения (400 → „не е намерен“, 401 → „не е публикуван“, 429); повторен импорт на запомнен източник не дублира записите (заменя предишния импорт само при отметнато „Запомни“); заключване срещу двоен клик. Автоматична (планирана) синхронизация **няма** — само ръчна. |
| REST API | `Retry-After` при 429 се губеше; нов незадължителен `Idempotency-Key` (24 ч., 422/409/400); `WWW-Authenticate: Bearer error="invalid_token"`; документацията на страницата е сверена с реалните отговори (кодове 400/403/409/413/415/500, лимити от `config/databackd-api.php`). |
| Микроинвест | Счетоводната програма е **Делта Pro** (Склад Pro е складова и само подава операции към нея) — текстът е поправен; шаблоните следват полетата от ръководството (Справки → Оборотна ведомост / Хронологичен регистър, експорт към Excel). |
| Ажур L (Бонев Софт) | Експортът е само към Excel; менюта и Дт/Кт според документацията на bsoft.bg. |
| Плюс Минус | Реалните колони на журнала (`Номер`, `Коментар`, `Сума` в базова валута); валутата не се преизчислява втори път. |
| Бизнес навигатор (Комерс Финанс) | Колони според ръководството (Период, Статия, Сметка, Кореспондираща сметка, Дебит/Кредит; „прав и обратен запис“), Windows-1251. |
| Шаблони (общо) | Заглавни редове над таблицата и двуредови заглавия („Начално салдо“ над „Дебит / Кредит“); редове „Общо“ на кирилица; аналитични сметки (602/1, 6021) към синтетичната от сметкоплана без двойно броене; приключвателни записвания се пропускат; нова отметка „Ведомостта е след приключване на годината“ (иначе — нетни обороти); десетичен знак по колона. |
| Банкови извлечения | MT940 в Windows-1251 излизаше нечетим (без да се чупи Windows-1252); краен ред `-}{5:…}`; `:86:` след крайното салдо; CAMT.053: пакетни записи с части с различен знак, контрагент при връщания, междинни салда (ITBD) само когато са достатъчни. XXE защитата и дубликатите са проверени. |
| Синхронизация от фактури и разходи | Платени фактури с кредитно известие изпадаха; BGN документи се превръщаха 1:1 (сега по 1,95583); промени/анулиране/изтриване на документа се отразяват; заключване; контрагент = фирмата на клиента; полетата, които идват от документа (дата, сума, валута, контрагент, номер), са само за четене в записа; бутонът иска потвърждение и има преглед. |
| Страницата | Уводът вече не казва „(скоро) счетоводни системи“; бутонът за синхронизация се показва само с модула `databackd_data`; изтекла сесия/CSRF не се показва като успех. |

## Отворени точки

- Колоните на четирите счетоводни програми са по документацията и ръководствата им, не по реален файл — при първия реален експорт от клиент да се свери (особено кодировка, десетичен знак, заглавни редове).
- API токените нямат срок и обхват (нужна е миграция).
- Разходите нямат ДДС поле → сумите им са брутни, а на фактурите — нетни.
- Нито една от четирите програми няма публично API за счетоводни данни; по-дълбока интеграция е възможна чрез SAF-T (Бизнес навигатор има платен модул) или Open Banking (PSD2, стандарт BISTRA) за банките — препоръка за следващ етап.

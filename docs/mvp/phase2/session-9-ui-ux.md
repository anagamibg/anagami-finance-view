# Сесия 9 — UI/UX: сайдбар, страници, графики

Прочети `docs/mvp/phase2/COMMON-RULES-2.md` и всичко, което то изисква. Ти си **S9** — оркестратор с до 10 агента. Вълна 1 (паралелно с S6 и S8 — ти притежаваш визуалния слой, виж правило 5). Без сървър, без branch, без push, без деплой. **Текстовете не ги пипаш** (S7 ги превежда и уеднаквява главните букви след теб) — само разметка, стилове, графики, компоненти.

Цел: интерфейсът да изглежда като модерен финансов SaaS продукт — подреден сайдбар, ясна йерархия, еднакви карти/таблици/форми, красиви и четими графики, добре и на мобилен.

## Фаза 0 — ти
1. **Проучване на best practices** (WebSearch, 6–10 източника, 2024–2026): навигация в B2B SaaS/дашбордове (сайдбар — групиране, активно състояние, сгъване, иконки), дизайн на финансови табла (KPI карти, йерархия, плътност), визуализация на данни (типове графики за финансови данни, цветове, достъпност/контраст, tooltips, празни състояния, форматиране на числа), таблици с данни, форми, мобилен. Ползвай skill-овете `dataviz` и `frontend-design`, ако са налични. Резултат: `docs/mvp/phase2/ui-guidelines.md` — кратки, конкретни правила за ТОЗИ проект (палитра с hex и CSS променливи, типография, разстояния, радиуси, сенки, правила за графики — палитра за серии, приход=зелено/разход=червено/печалба=синьо и т.н., формат € и хиляди с интервал, легенди, оси).
2. **Инструмент за визуална проверка без сървър** `docs/mvp/tools/snapshot.php` + `snapshot.js`: PHP рендира страница (като `smoke.php`) и записва HTML в scratchpad с `<base href="file://…/public/">`; Node с Playwright (`/Users/tsvet/Documents/Projects/kukie.io/kukie/node_modules/playwright`, headless Chromium вече е свален) отваря файла и прави PNG на 1440×900 и 390×844. Употреба: `php docs/mvp/tools/snapshot.php <url> [--email=] [--out=]`. Документирай го в COMMON-RULES-2 (секция 1 вече го споменава). Агентите го ползват, за да **виждат** резултата (Read на PNG).
3. **Дизайн система (споделена основа за агентите):** `resources/scss/databackd/_tokens.scss` (CSS променливи от насоките, вкл. тъмна тема, ако приложението има такава), `_components.scss` (карти, KPI, табове, бутони, филтри, таблици, празни състояния), включени в `main.scss`; `resources/js/databackd-charts.js` — обща тема за Chart.js (палитра, шрифт, tooltips с `Intl.NumberFormat('bg-BG', {style:'currency', currency:'EUR'})`, оси с хиляди, легенди, responsive, анимации) и helper-и (`dbkChart.bar/line/donut/combo/sparkline`) — заредени глобално. Пусни `npm run prod` веднъж и провери, че компилира.
4. Снимки „преди“ на 10 ключови страници (сайдбар, табло, финансово табло, записи, справки, ОПР, коефициенти, консолидация, бюджет, заявки за екип) → `docs/mvp/phase2/ui-before/`.

## Фаза 1 — пакети (наведнъж; агентите НЕ пускат `npm`; ако им трябва SCSS — пишат в свой partial `resources/scss/databackd/_<пакет>.scss`, който ти си включил в `main.scss` предварително като празен файл; компилираш ти във Фаза 2)
| Пакет | Обхват |
|---|---|
| P1 сайдбар и топбар | `sections/sidebar|menu|topbar`, `components/menu-item|sub-menu-item`: групиране с разделители и заглавия на групи (напр. „Анализ“, „Операции“, „Администрация“), еднакви иконки (Bootstrap Icons), ясно активно състояние на пункт и подпункт, по-добри разстояния и контраст, сгънат режим с tooltips, логото/името на компанията да не се реже, мобилно меню. Разделът „Финансов анализ“ е дълъг (~30 пункта) — подгрупи (Данни, Справки, Анализи, Планиране, Екипи) със заглавия. **Текстът на пунктовете не се сменя.** |
| P2 заглавия и layout | `layouts/app`: page header (заглавие + описание + действия вдясно), breadcrumbs, ширина/поле на съдържанието, фон, карти; празни състояния и loader-и. |
| P3 финансово табло + основно табло | `databackd/reports/dashboard/**`, `dashboard/**`: KPI карти по насоките (иконка, стойност, промяна със стрелка и цвят, sparkline), графики през `dbkChart`, подредба по важност. |
| P4 справки | конструктор, ОПР, паричен поток, контрагенти, запазени справки — таблици (фиксиран header, зебра, числа вдясно, отрицателни в червено), графики. |
| P5 коефициенти и консолидация | карти на коефициентите (светофар, gauge/sparkline), детайл, сравнение (heatmap), консолидационна таблица — **да не се отрязва** (хоризонтален скрол с фиксирана първа колона), графики на приноса. |
| P6 планиране | бюджети, редактор (grid като в spreadsheet — фиксирани колони, редове с групи), бюджет vs реално (bullet/variance графика), прогнози (коридор, сценарии). |
| P7 екипи | заявки за екип (карти за размер на екипа), детайл с timeline, Kanban, специалисти (карти). |
| P8 данни и импорт | записи, множествено въвеждане, импорт съветник (stepper), история, интеграции (карти), сметкоплан (дърво), разрези. |
| P9 стандартни модули | клиенти, договори, проекти, задачи, фактури, плащания, разходи, банкови сметки, продукти — само общи подобрения през компонентите/CSS (без пренаписване на views). |
| P10 мобилен и достъпност | преглед на всички горни на 390 px; контраст (WCAG AA), фокус, размер на зоните за клик; поправки в partials/CSS. |

Всеки агент: спазва `ui-guidelines.md`, ползва `dbkChart` за всички графики, прави снимки преди/след на своите страници със `snapshot`, пуска smoke на своите routes.
